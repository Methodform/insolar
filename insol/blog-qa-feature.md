# Инсоляр — «Открытые вопросы» под статьями (модерируемый Q&A)

> Решение: модерируемый Q&A. Посетитель задаёт вопрос → он уходит в очередь → автор одобряет и отвечает → вопрос с ответом появляется публично под статьёй.
> Условие: сайт переезжает на отдельный сервер (бэкенд есть). Идентификация — без иностранной авторизации (закон от 07.2026): либо без входа, либо Яндекс ID (уже интегрирован).
> Обновлено: 2026-07-27.

---

## Зачем (польза для проекта)

- **Свежий уникальный текст под SEO** — люди пишут ровно теми словами, что ищут; растут дочитывания (поведенческий фактор №1 для Яндекса).
- **Разметка `QAPage`** → шанс на расширенные сниппеты и «быстрые ответы».
- **Бесконечный источник тем** для новых статей и пополнения FAQ.
- **Мост к монетизации** — в ответе уместна ссылка «проверьте свой участок» → сервис → паспорт.
- **Живость и доверие** — реальная экспертная лента вместо пустой статьи.

Спам не попадает в индекс, потому что публикуется только после ручного одобрения.

---

## Пользовательский флоу

1. Под статьёй блок «Задать вопрос по теме»: поле вопроса, имя, необязательный e-mail (чтобы прислать уведомление, когда ответят).
2. Отправка → «Спасибо, вопрос отправлен на модерацию, ответ появится под статьёй».
3. Автор в админке видит очередь, одобряет/отклоняет, пишет ответ.
4. Одобренный вопрос + ответ рендерятся в статье (server-side) с разметкой `QAPage`.
5. Если оставлен e-mail — письмо «на ваш вопрос ответили» со ссылкой на статью (повторный заход).

Идентификация: по умолчанию **без входа** (имя + e-mail опционально) — так больше вопросов. Вход через **Яндекс ID** — опция для тех, кто хочет отслеживать свои вопросы (переиспользуем уже готовый `yandexAuth.js`). Иностранную авторизацию не подключаем.

## Модель данных (минимум)

```
question:
  id            uuid
  article_slug  string        // к какой статье
  body          text          // сам вопрос
  author_name   string
  author_email  string|null   // не показывается публично
  status        enum(new, approved, rejected)
  answer        text|null      // ответ автора
  created_at    datetime
  answered_at   datetime|null
  ip_hash       string         // для антиспама/лимитов (хэш, не сырой IP)
```

## API (на своём сервере)

- `POST /api/qa` — принять вопрос `{article_slug, body, author_name, author_email?}`. Валидация, антиспам, `status=new`. Возвращает 202.
- `GET  /api/qa?article_slug=…` — вернуть только `approved` (для рендера/подгрузки).
- `POST /api/qa/{id}/approve` — одобрить + сохранить `answer` (только админ, за авторизацией).
- `POST /api/qa/{id}/reject` — отклонить (только админ).

Публичные страницы статей должны **рендерить одобренные Q&A в HTML на сервере** (не подгружать JS), иначе краулер их не увидит — это то же требование SSR, что и для всего сайта.

## Антиспам (без капчи, где можно)

- **Honeypot-поле** (скрытый input; боты заполняют — реджект).
- **Rate-limit** по хэшу IP: не больше N вопросов в час.
- **Проверка на ссылки/HTML** в теле (режем/флагаем вопросы со ссылками — типичный спам).
- **Ручная модерация** — последний фильтр: ничего не публикуется без одобрения.
- Капча — только если польёт спам; тогда российская (например, Yandex SmartCaptcha), не reCAPTCHA.

## SEO-разметка (важно)

Для страницы статьи с вопросами — JSON-LD `QAPage` со списком `Question` → `acceptedAnswer`. Пример одного вопроса:

```json
{"@context":"https://schema.org","@type":"QAPage","mainEntity":{
  "@type":"Question","name":"Текст вопроса пользователя",
  "answerCount":1,
  "acceptedAnswer":{"@type":"Answer","text":"Ответ автора","author":{"@type":"Organization","name":"Инсоляр"}},
  "author":{"@type":"Person","name":"Имя посетителя"},
  "datePublished":"2026-08-01"}}
```

Нюанс: на одной странице уже есть `FAQPage`. `FAQPage` — для вопросов, которые задаёт сам сайт; `QAPage` — для пользовательских. Их можно держать раздельно (FAQ-блок редакции + Q&A-лента посетителей), это корректно.

## Вёрстка (блок в статью)

- Секция «Вопросы читателей» после FAQ, перед футером: список одобренных Q&A (вопрос — автор/дата — ответ редакции) + форма «Задать вопрос».
- Готовый статический каркас блока можно вставить в шаблон статьи уже сейчас (форма + место под ленту), а `action`/подгрузку подключить, когда поднимем сервер.

## Админка

Проще всего — добавить в существующую админ-панель (`AdminApp.jsx`, раздел «Контент») вкладку **«Вопросы»**: очередь `new`, кнопки «Ответить и опубликовать» / «Отклонить», поиск по статье. Данные — из `GET/POST /api/qa`.

## Когда включать

Не на старте: пока трафика нет, лента будет пустой. Включаем, когда на статьях появятся стабильные визиты и реальные вопросы (ориентир — из GTM: ≥500 визитов/мес). До этого на страницах достаточно редакционного FAQ-блока.

## Этапы внедрения

1. Поднять сервер и БД (одна таблица `question`).
2. `POST /api/qa` + honeypot + rate-limit.
3. Вкладка «Вопросы» в админке (модерация + ответ).
4. Server-render одобренных Q&A в статьи + `QAPage` разметка.
5. (Опция) уведомления на e-mail и вход через Яндекс ID.
6. (Опция) Yandex SmartCaptcha, если польёт спам.
