# Инсоляр — настройка Яндекс.Вебмастера и Google Search Console

> Сайт: https://methodform.github.io/insolar/ (проект на GitHub Pages, подпуть `/insolar/`).
> Цель: попасть в индекс обоих поисковиков, отправить sitemap, включить быструю переиндексацию.
> Обновлено: 2026-07-26.

---

## Важно про GitHub Pages и подпуть

Сайт живёт по адресу `https://methodform.github.io/insolar/`. Это **URL-префикс**, а не отдельный домен. Поэтому:
- В обоих сервисах добавляем ресурс **именно с путём** `/insolar/`, а не голый `methodform.github.io`.
- Файлы верификации, которые нужно положить «в корень», кладём в папку `insol/` репозитория — она публикуется как `/insolar/`. То есть файл `insol/yandex_xxx.html` откроется по `https://methodform.github.io/insolar/yandex_xxx.html`.
- Оба способа подтверждения работают: **мета-тег** (плейсхолдеры уже добавлены в `landing.html`) или **HTML-файл** (положить в `insol/`).

## 1. Яндекс.Вебмастер (приоритет — основная аудитория в РФ)

1. Зайти на **webmaster.yandex.ru** под своим Яндекс-аккаунтом → «Добавить сайт».
2. Ввести адрес: `https://methodform.github.io/insolar/`.
3. Выбрать способ подтверждения:
   - **Мета-тег (проще):** Яндекс покажет `<meta name="yandex-verification" content="КОД">`. Скопировать `КОД` и вставить вместо `ВСТАВЬТЕ_КОД_ЯНДЕКСА` в `landing.html` (строка уже есть в `<head>`). Задеплоить. *Примечание:* мета-тег Яндекс проверяет на странице ресурса; т.к. корень `/insolar/` — это сервис (React), надёжнее способ ниже.
   - **HTML-файл (надёжнее для подпути):** скачать файл вида `yandex_xxxxxxxx.html`, положить его в папку `insol/` репозитория, задеплоить, проверить что открывается по `https://methodform.github.io/insolar/yandex_xxxxxxxx.html`, нажать «Проверить».
4. После подтверждения: **«Индексирование» → «Файлы Sitemap»** → добавить `https://methodform.github.io/insolar/sitemap.xml`.
5. **«Индексирование» → «Переобход страниц»** → добавить лендинг и статьи для ускоренной индексации.
6. Проверить: «Инструменты» → «Проверка мобильных страниц», «Валидатор микроразметки».

## 2. Google Search Console

1. Зайти на **search.google.com/search-console** → «Добавить ресурс» → тип **«Ресурс с префиксом URL»**.
2. Ввести: `https://methodform.github.io/insolar/`.
3. Способ подтверждения:
   - **HTML-тег:** Google даст `<meta name="google-site-verification" content="КОД">`. Вставить `КОД` вместо `ВСТАВЬТЕ_КОД_GOOGLE` в `landing.html`. Задеплоить, нажать «Подтвердить».
   - **HTML-файл:** скачать `googleXXXX.html`, положить в `insol/`, задеплоить (откроется по `/insolar/googleXXXX.html`), подтвердить.
4. **Sitemaps** (левое меню) → добавить `sitemap.xml` (полный URL `https://methodform.github.io/insolar/sitemap.xml`).
5. **Проверка URL** (верхняя строка) → вставить URL лендинга → «Запросить индексирование».
6. Позже смотреть: «Покрытие/Страницы», «Эффективность» (запросы), «Core Web Vitals», «Удобство для мобильных».

## 3. IndexNow (мгновенная переиндексация в Яндексе — бесплатно)

IndexNow позволяет пинговать поисковик при каждом обновлении контента — статьи попадают в индекс за часы, а не недели.
1. В Яндекс.Вебмастере: «Индексирование» → «IndexNow» → сгенерировать/скачать ключ (файл `<ключ>.txt`).
2. Положить файл ключа в папку `insol/` (откроется по `/insolar/<ключ>.txt`), задеплоить.
3. При публикации новой статьи пинговать (можно вручную из браузера):
   `https://yandex.com/indexnow?url=https://methodform.github.io/insolar/НОВАЯ-СТАТЬЯ.html&key=ВАШ_КЛЮЧ`
4. (Опционально) автоматизировать пинг в GitHub Actions после деплоя.

## 4. Яндекс.Метрика (аналитика — без неё стратегию не измерить)

1. **metrika.yandex.ru** → создать счётчик для `methodform.github.io/insolar`.
2. Вставить код счётчика перед `</head>` в `landing.html` (и, при желании, в статьи и `index.html`).
3. Настроить **цели:** клик по «Открыть сервис / Проверить участок», переход в сервис, регистрация, покупка «паспорта».
4. Включить **Вебвизор** и карту кликов — увидеть, как ведут себя пользователи на лендинге.
5. (Google-аналог — Google Analytics 4, по желанию; для РФ достаточно Метрики.)

## Частые проблемы

- **«Страница не проиндексирована»** у главной `/insolar/` — ожидаемо: это React-приложение, краулер видит пустой каркас. Индексируем лендинг и статьи (статический HTML). На перспективу — пререндер сервиса.
- **Верификация не проходит** — проверьте, что файл/мета реально доступен по нужному URL после деплоя (жёсткое обновление, очистка кэша), и что путь именно `/insolar/...`.
- **Sitemap не читается** — откройте `https://methodform.github.io/insolar/sitemap.xml` в браузере: должен отдавать XML, а не 404.
